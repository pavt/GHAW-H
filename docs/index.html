Dataset overview

A longitudinal view, not a flat inventory.

Each published row preserves an observable GitHub artifact or API fact. GHAW-H separates immutable content from temporal position, making workflow evolution reproducible and auditable.

01

Observed adoption over time

Repository-level adoption is derived from the earliest observable committed workflow version, while the underlying version records remain available for independent analysis.

02

Language context

Repository language metadata enables ecosystem-level comparisons without inferring language from workflow content.

03

History depth

Version chains expose how often workflow specifications change and how long their observable histories span.

Relational schema

Five tables. One traceable evidence path.

repository262 rows

Observed identity, ownership, language, activity, and popularity metadata.

source_markdown_file_history604 rows

Longitudinal identity for each confirmed workflow source.

source_markdown_file_snapshot2,820 rows

Literal Markdown, frontmatter, body, path, and repository relationship.

source_markdown_file_version2,820 rows

Commit metadata, rank, history membership, and neighbor links.

lock_file_snapshot2,820 rows

Lock content and file SHA aligned one-to-one with a source version.
