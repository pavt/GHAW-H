About the challenge

GitHub Agentic Workflows (GH-AW) are an emerging form of repository automation in which developers define agentic workflows in Markdown and execute them through GitHub Actions. A GH-AW specification combines structured configuration in the frontmatter with task instructions expressed in natural language, and is compiled into a lock file that runs as a GitHub Actions workflow.

The GHAW-H dataset provides an empirical basis for studying these agentic workflow specifications and their evolution. It contains the histories of GH-AW files collected from public GitHub repositories that used the tool during its early adoption period. Each observed version preserves the source Markdown specification, including its literal frontmatter and natural-language body, together with the corresponding compiled lock file and version-history information.

Research opportunities

GHAW-H supports the study of natural-language agentic workflow specifications from multiple perspectives. Potential research directions include, but are not limited to:

  • Instruction structure and developer intent: How do GH-AW specifications express the intended behavior of an agent, and which software engineering activities are automated through these instructions?
  • Instruction quality and specification defects: To what extent do instructions contain ambiguous, incomplete, redundant, contradictory, or unverifiable statements?
  • Instruction–configuration consistency: Do the permissions, tools, and triggers declared in the frontmatter support the behavior requested in the natural-language instructions?
  • Specification-to-workflow traceability: How are instructions reflected in the jobs, steps, conditions, and permissions of the compiled lock files?
  • Workflow evolution and maintenance: How do natural-language instructions, frontmatter configurations, and compiled workflow definitions evolve across versions?
  • Workflow similarity and reuse: Which GH-AW specifications express similar software engineering goals, and how can existing specifications be retrieved or reused for new automation tasks?
  • Comparative studies: How do GH-AW specifications differ from configurations, instructions, or workflows associated with other agentic coding tools or repository automation mechanisms?
  • Methods and tools: How can NLP, machine learning, LLM-based approaches, or other empirical software engineering techniques support the analysis, understanding, validation, or development of GH-AW specifications?

These directions are examples rather than an exhaustive research agenda. Researchers are encouraged to formulate additional questions enabled by the dataset.

Different types of contributions are welcome, including empirical studies, tool-oriented papers, comparative studies with related datasets, and replication or extension studies.

Dataset

The GHAW-H release includes:

  • repository-level metadata;
  • histories of confirmed GH-AW source Markdown files;
  • source Markdown snapshots containing the complete specification, literal YAML frontmatter, and natural-language body;
  • ordered source-file versions with commit SHA, timestamp, predecessor, successor, and version rank; and
  • commit-aligned compiled *.lock.yml snapshots.

The release also provides reproducible Jupyter notebooks, the dataset schema, table documentation, and supporting visualizations.

How to participate

Use GHAW-H to investigate a research problem related to Natural Language-based Software Engineering and GitHub Agentic Workflows.

Researchers may analyze individual artifacts, relationships among artifacts, or their evolution over time. GHAW-H may also be combined with additional data when relevant to the research problem.

The choice of study design and analysis method is open. Contributions may employ quantitative, qualitative, or mixed empirical methods, including NLP, machine learning, LLM-based analysis, mining software repositories, manual analysis, or other approaches appropriate to the research question.

Submissions

A GitHub Agentic Workflows Challenge paper should describe the results of the work by providing:

  • an introduction to the software engineering problem being addressed, its relevance to Natural Language-based Software Engineering, and why it is worth studying;
  • the version of the GHAW-H dataset used;
  • the research question or problem investigated;
  • the approach and tools used;
  • the results and their implications; and
  • the conclusions of the work.

The paper should clearly highlight its contributions and their importance.

Authors who augment GHAW-H with additional data should describe the corresponding data sources and collection or extraction procedures. Authors are also encouraged to make analysis code, derived data, tools, and other research artifacts available to support reproducibility.
